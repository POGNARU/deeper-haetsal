Deeper · Shared Prompt

내 아카이브 페이지 만들기

인사이트와 과제를 한자리에 모아두는 웹 아카이브를, 클로드와 함께 직접 짓는 프롬프트입니다.

살롱에서 쌓이는 것들은 흩어지기 쉽습니다. 이번 주에 만든 결과물, 과제로 캐낸 문장 — 어딘가에는 다 있는데 한자리에는 없습니다. 이 프롬프트는 그것들이 모이는 자리를 하루 만에 짓게 해줍니다.

디자인은 각자 다르게 나옵니다. 프롬프트 맨 앞에 색과 이름을 스스로 정하는 인터뷰가 있어서, 같은 뼈대 위에 자기 결이 입혀집니다. 저와 똑같은 페이지가 나오지 않습니다.

STEP 1
복사한다
아래 프롬프트 전문을 복사 버튼으로 한 번에 가져갑니다
STEP 2
붙여넣는다
클로드(Claude 또는 Claude Code) 새 대화에 그대로 붙여넣습니다
STEP 3
대화한다
클로드가 묻는 것에 답하다 보면 내 색을 가진 아카이브가 나옵니다

프롬프트 전문

이 아래 전부를 클로드에게 붙여넣으세요 
너는 나의 개인 아카이브 사이트를 짓는 개발·디자인 파트너야.
나는 디퍼 언브랜딩 살롱의 연구원이고, 살롱에서 쌓은 **인사이트(주간 성찰)**,
**과제 결과물**을 한자리에 모아두는 공개 웹 아카이브를 만들고 싶어.

정적 HTML만 쓰고(빌드 도구·프레임워크 없이), GitHub Pages로 배포한다.
아래 순서대로 진행해줘.

## 1단계 — 먼저 나에게 물어봐 (만들기 전에)

한 번에 다 묻지 말고, 아래 묶음을 순서대로 물어보고 내 답을 받은 뒤 다음으로 넘어가.
내가 "모르겠다"고 하면 네가 두세 가지 안을 제시하고 고르게 해줘.

**(1) 정체**
- 아카이브에 쓸 내 이름/닉네임은?
- 나를 한 줄로 소개한다면? (랜딩에 들어갈 태그라인)
- 브랜드나 스튜디오 이름이 따로 있나? 없으면 이름만 쓴다.

**(2) 색과 글꼴**
- 이미 정한 브랜드 색이 있나? 있으면 HEX로 알려줘.
- 없으면 내가 좋아하는 것(계절·시간대·풍경·사물)을 물어보고,
  거기서 **5색 팔레트**를 제안해줘 — 배경 / 강조 / 보조 / 포인트 / 본문글자.
  - 배경은 흰색보다 살짝 물든 색을 권한다(눈이 편하고 개성이 산다).
  - 본문 글자와 배경의 명도 대비는 **4.5:1 이상**이어야 한다. 계산해서 확인하고 알려줘.
  - 밝은 노랑·연한 파스텔은 **선·아이콘 전용**으로 두고 글자색으로 쓰지 마.
- 글꼴은 구글폰트에서 한글 3종을 고른다 — 제목용 / 본문용 / 캡션용.
  기본 제안: 제목 Gowun Batang · 본문 Nanum Myeongjo · 캡션 Gowun Dodum.
  다른 결을 원하면 두세 조합을 보여주고 고르게 해줘.

**(3) 담을 것**
- 랜딩에 둘 큰 갈래는 둘이다 — 인사이트 · 과제.
  살롱 밖의 것(독서 기록·개인 프로젝트 등)을 더하고 싶으면 지금 말해줘. 같은 규칙으로 폴더를 하나 더 만든다.
- 각 갈래를 뭐라고 부를까? (예: 인사이트 / 기록 / 주간 성찰)
- 이미 만들어 둔 결과물(웹페이지·노션·블로그 글)이 있으면 주소를 알려줘 — 카드로 걸어둔다.

**(4) 공개 범위**
- 검색엔진에 노출할까, 링크를 아는 사람만 들어오게 할까?
  (권장: **노출하지 않음.** 살롱 기록에는 사적인 대목이 섞이기 쉽다)
- 깃허브 계정 이름과 만들 저장소 이름을 알려줘.

답을 다 받으면 **정리해서 보여주고 내 확인을 받은 뒤** 만들기 시작해.

## 2단계 — 이 구조로 만들어줘

```
저장소루트/
├─ index.html               랜딩 — 인사이트 · 과제 두 갈래 카드
├─ insight/
│   ├─ index.html           인사이트 목록 (최신이 위)
│   └─ YYMMDD.html          주간 인사이트 리포트 한 편
├─ assignment/
│   ├─ index.html           과제 목록 (카드 그리드)
│   └─ YYMMDD-이름.html      과제 결과물 페이지
├─ assets/                  이미지·아이콘
├─ favicon-32.png           탭 아이콘
├─ favicon-180.png          애플 터치 아이콘
├─ .github/workflows/deploy.yml
└─ README.md
```

### 랜딩(index.html)
- 화면 한가운데 세로 정렬. 스크롤 없이 한눈에 들어오게.
- 위에서부터: 작은 영문 라벨(EYEBROW) → 큰 이름 → 태그라인 → 짧은 구분선 → 카드 → 푸터.
- 카드는 가로 배치(모바일에서 세로로 접힘). 각 카드에 원형 아이콘 + 이름 + 두 줄 설명.
- 카드마다 강조색을 다르게 줘서 갈래가 눈으로 구분되게.
- hover에 살짝 떠오르는 움직임(transform + shadow) 정도만. 과하지 않게.

### 목록 페이지(insight/index.html 등)
- 맨 위에 `← 이름` 돌아가기 링크.
- **인사이트는 세로 리스트** — 항목마다 `날짜 범위 / 제목 / 한 줄 요약`.
  왼쪽에 강조색 세로줄을 넣어 리듬을 준다. hover엔 오른쪽으로 살짝 밀리는 움직임.
- **과제는 카드 그리드** (`repeat(auto-fill,minmax(220px,1fr))`) — `태그 / 제목 / 한 줄 설명`.
  카드 위쪽에 강조색 가로줄. 중요한 것은 `featured`로 한 줄 전체 차지.
- 아직 채워지지 않은 칸은 점선 테두리 자리표시로 남겨둬 — 자라는 아카이브라는 게 보이게.

### 모든 페이지 공통 규격
- `<html lang="ko">`, 모바일 뷰포트 메타 필수.
- 색은 전부 `:root`의 CSS 변수로. 색을 바꿀 때 한 곳만 고치면 되게.
- 외부 CSS·JS 라이브러리를 쓰지 말고 각 파일 안에 인라인으로 둬. (구글폰트 링크만 예외)
- 파비콘은 **상대경로**로 건다 — 루트는 `favicon-32.png`, 하위 폴더는 `../favicon-32.png`.
  GitHub Pages 프로젝트 사이트는 `/저장소명/` 아래로 서빙되므로 `/favicon-32.png` 같은
  루트 절대경로를 쓰면 아이콘이 깨진다.
- 외부 사이트로 나가는 링크만 `target="_blank" rel="noopener noreferrer"`.
  아카이브 안에서 도는 링크는 같은 탭으로.
- 푸터는 모든 페이지에 같은 문구로.
- 검색 노출을 원하지 않기로 했다면 **모든 페이지의 `<head>`에**
  `<meta name="robots" content="noindex, nofollow">`를 넣는다. 새 페이지를 더할 때도 빠짐없이.

## 3단계 — 콘텐츠를 쌓는 규칙 (README에 적어둘 것)

이 규칙은 나중에 내가(또는 다른 클로드 세션이) 페이지를 더할 때 지켜야 하는 약속이야.
README.md에 그대로 적어줘.

**파일명은 `YYMMDD.html`**로 통일한다. 날짜순으로 자연히 정렬되고,
새 글은 같은 규칙으로 떨어뜨리면 목록에 한 줄씩 쌓인다.
같은 날 여러 개면 `YYMMDD-키워드.html`.

**인사이트 리포트는 "결과물 먼저, 성찰 나중"으로 쓴다.**
- 먼저: 그 주에 실제로 만든 것을 눌러볼 수 있게 보여준다. 링크·이미지·카드,
  그리고 **어떻게 만들었는지(쓴 프롬프트·방법)를 같이 공유**한다. 이게 리포트의 중심이다.
- 나중에: 성찰은 하단에 **짧은 항목(제목 + 한두 줄)** 요약으로. 긴 문단으로 풀지 않는다.

**성찰은 내 것만 쓴다.**
- 내가 실제로 겪고 느낀 것만 성찰에 넣는다. AI가 조사·판단한 내용은 성찰이 아니다.
- 내가 쓰지 않는 단어를 얹지 않는다. 그럴듯한 요약보다 실제로 한 일을 그대로.
- AI(에이전트)가 어떻게 판단하고 일했는지는 **별도 섹션에 그 목소리로** 싣는다.
  살롱에서 이 꼭지가 특히 도움이 된다는 반응이 있었다.
- 비유보다 직접적인 표현을 쓴다.

**공개 저장소라는 걸 잊지 않는다.**
- 병력·가족·실명·사연 같은 사적인 내용은 공개본에 싣지 않는다.
  과제가 개인의 몸이나 건강을 다룰 땐 **내 응답·증상은 빼고 일반 자료로만** 정리한다.
- 원본(사적인 대목이 든 정본)은 로컬이나 비공개 저장소에만 둔다.
  공개본은 그 **사본**이고, 고칠 일이 생기면 **정본을 먼저 고치고 다시 옮긴다.**
- 공개본에 다른 사람과의 관계나 거리를 적지 않는다 — 당사자가 읽는다.

**팔레트 예외는 문서로 남긴다.**
어떤 결과물 페이지는 자기 고유의 색을 갖는 게 맞다(상품 상세·발표 슬라이드 등).
그럴 땐 아카이브 팔레트를 벗기고 그 색을 쓰되, **왜 예외인지 README에 한 줄 적는다.**

**새 페이지를 더한 뒤엔 세 곳을 같이 고친다** — ① 목록 index.html에 카드/항목 한 줄,
② README의 구조 트리와 표, ③ 커밋.

## 4단계 — 배포

`.github/workflows/deploy.yml`을 아래 내용으로 만들어줘. main에 푸시하면 자동 배포된다.

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: pages
  cancel-in-progress: true
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: .
      - id: deployment
        uses: actions/deploy-pages@v4
```

만든 뒤 나에게 알려줘:
- 깃허브 저장소 Settings → Pages → Source를 **GitHub Actions**로 바꿔야 첫 배포가 돈다.
- 저장소를 public으로 두더라도 `noindex`면 검색에는 안 잡히지만 **주소를 아는 사람은 읽을 수 있다.**
  완전히 감추려면 저장소를 private으로 두고 Pages를 끈다.
